# Writing for agents

Write guidance that changes useful decisions: project facts, non-obvious
invariants, fragile procedures and demonstrated failure corrections. Leave routine
engineering judgment to the agent. Keep each policy in one authoritative place.

Front-load the actual trigger in a short description or conditional pointer.
Separate substantial modes into referenced files; keep shared essentials in the
entrypoint. A reference should say when it is needed, not demand every document
before every edit. Avoid a router when a focused instruction is sufficient.

State inputs, expected outcomes, relevant evidence and stopping conditions.
Preserve the user's intent, existing approvals and unrelated work. Scale process,
testing and checkpoints to the task instead of mandating an itinerary or agent
count. Keep real boundaries explicit without asking repeatedly for safe work
already authorized.

For Codex packaging and invocation policy, use
[SKILL-MECHANICS.md](SKILL-MECHANICS.md) and the available Skill Creator skill.
For a requested retrospective, use [RETRO.md](RETRO.md). Improve instructions from
actual outcomes; compare representative tasks before claiming quality or token
savings. Retain attribution for adapted material in [UPSTREAM.md](../../UPSTREAM.md).
